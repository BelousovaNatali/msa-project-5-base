# Метрики для мониторинга системы TradeWare

## 1. Бизнес-метрики

| № | Метрика                         | Описание                                | Порог                        |
|---|---------------------------------|-----------------------------------------|------------------------------|
| 1 | Количество загруженных отчётов  | Число CSV-файлов, загруженных за период | Сравнение с предыдущим днём  |
| 2 | Количество обработанных записей | Общее число строк, прошедших ETL        | Сравнение с прогнозом        |
| 3 | Успешность выполнения Job       | Процент успешных пакетных задач         | > 5% ошибок за час           |
| 4 | Время обработки отчёта          | Время от загрузки до завершения ETL     | > 30 секунд (для 2000 строк) |

## 2. Технические метрики

| № | Метрика                             | Описание                            | Порог срабатывания             |
|---|-------------------------------------|-------------------------------------|--------------------------------|
| 1 | Время выполнения Job                | Длительность Spring Batch Job       | > 30 секунд                    |
| 2 | Скорость обработки                  | Записей в секунду                   | < 100 записей/сек              |
| 3 | Количество retry                    | Число повторных попыток при ошибках | > 10% от общего числа операций |
| 4 | HTTP-статусы ответов                | 2xx, 4xx, 5xx                       | > 5% ошибок 5xx                |
| 5 | Задержка API (latency)              | Время ответа API                    | p95 > 1 секунда                |
| 6 | Использование памяти JVM            | Heap / Non-Heap memory              | > 85% от максимума             |
| 7 | CPU Usage                           | Загрузка процессора                 | > 80% в течение 5 минут        |
| 8 | Время выполнения запросов к БД      | Медленные запросы                   | > 10 запросов > 1 сек в минуту |

## 6. Логирование

Все сервисы (монолит, Spring Batch, API Gateway) отправляют логи в централизованную систему:
- **Logstash** — принимает логи, обрабатывает и обогащает их (добавляет поля, парсит)
- **Elasticsearch** — хранит логи и индексирует их для быстрого поиска
- **Kibana** — предоставляет интерфейс для поиска, фильтрации и визуализации логов

### Формат лога (JSON)

Каждая запись лога имеет единую структуру в формате JSON. Пример:

```json
{
  "timestamp": "2026-06-21T20:00:00.000Z",
  "level": "INFO",
  "service": "spring-batch",
  "jobName": "importInventoryJob",
  "readCount": 2000,
  "writeCount": 2000,
  "skipCount": 0,
  "duration": 25000,
  "user": "worker@tradeware.com",
  "filename": "inventory_2026-06-21.csv",
  "message": "Job completed successfully",
  "traceId": "abc-123-def-456"
}
```

### Что логируется

| Событие                      | Пример                                               |
|------------------------------|------------------------------------------------------|
| Загрузка файла пользователем | "Пользователь Иванов загрузил файл report.csv"       |
| Начало выполнения Job        | "Job importInventoryJob началась"                    |
| Окончание выполнения Job     | "Job закончилась за 25 секунд"                       |
| Статистика обработки         | "Прочитано 2000 записей, записано 1998, пропущено 2" |
| Ошибки                       | "Ошибка подключения к БД: Connection timeout"        |
| Предупреждения               | "Найдена запись с некорректным форматом"             |
