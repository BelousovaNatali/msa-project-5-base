# ADR: Выбор решения для пакетной обработки данных TradeWare

### **Название задачи:**
Выбор технологического решения для ETL-операций и пакетной обработки данных

Необходимо:
- Внедрить пакетную обработку для разгрузки онлайн-компонентов
- Обеспечить надёжную работу под возрастающей нагрузкой
- Соблюдать требования по производительности (обработка 2 000 строк до 30 секунд)
- Внедрить систему централизованного сбора логов и метрик
- Подготовить фундамент для миграции в микросервисную архитектуру

### Решение

Для реализации ETL-операций и пакетной обработки данных выбран **Spring Batch**.

### Логика принятия решения

Выбор Spring Batch основан на сравнении с основными альтернативами:

| Критерий                                | Spring Batch  | Apache Airflow   | K8s CronJob   | Apache Spark   |
|-----------------------------------------|---------------|------------------|---------------|----------------|
| Пакетная обработка (чанковая)           | Есть          | Ограниченно      | Нет           | Есть           |
| Транзакционность                        | Есть          | Нет              | Нет           | Ограниченно    |
| Retry-механизмы                         | Есть          | Есть             | Есть          | Есть           |
| Мониторинг и логирование                | Средняя       | Высокая          | Средняя       | Средняя        |
| Интеграция с Java                       | Высокая       | Средняя          | Низкая        | Низкая         |
| Горизонтальное масштабирование          | Есть          | Есть             | Есть          | Есть           |
| Сложность реализации для ETL            | Низкая        | Средняя          | Высокая       | Высокая        |
| Подготовка к микросервисной архитектуре | Есть          | Есть             | Нет           | Есть           |
| Ресурсоёмкость                          | Средняя       | Средняя          | Низкая        | Высокая        |

#### Описание работы ETL-пайплайна

1. **Загрузка** — сотрудник склада загружает CSV-файл через интерфейс ERP
2. **Валидация (Extract)** — Spring Batch читает файл и проверяет данные
3. **Трансформация (Transform)** — данные обогащаются справочной информацией
4. **Загрузка (Load)** — данные сохраняются в результирующую таблицу
5. **Уведомление** — пользователь получает уведомление о результате
6. **Мониторинг** — все этапы логируются и отправляются в централизованную систему

### Альтернативы

#### 1. Apache Airflow

**Плюсы:** мощный оркестратор с UI, DAG-пайплайны

**Минусы:** не оптимизирован для ETL-операций с большими объёмами, требует отдельной установки, Python-стек

#### 2. K8s CronJob

**Плюсы:** простота, низкая ресурсоёмкость

**Минусы:** нет встроенных ETL-механизмов

#### 3. Apache Spark

**Плюсы:** высокая производительность, масштабируемость

**Минусы:** избыточен для текущих объёмов, сложность настройки

---

### Итоговое решение

Выбран **Spring Batch** как наиболее подходящее решение, так как он:

- Закрывает 100% функциональных требований
- Имеет встроенные ETL-механизмы
- Поддерживает чанковую обработку для оптимизации нагрузки на БД
- Обеспечивает транзакционность и отказоустойчивость
- Предоставляет встроенные retry-механизмы
- Интегрируется с Java-экосистемой компании
- Имеет большой набор инструментов мониторинга
- Позволяет гибко масштабироваться под нагрузкой
